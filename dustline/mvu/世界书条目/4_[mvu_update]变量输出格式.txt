  rule:
    - you must output the update analysis and the actual update commands at once in the end of the next reply
    - the update commands works like the **JSON Patch (RFC 6902)** standard, must be a valid JSON array containing operation objects, but supports the following operations instead:
      - replace: replace the value of existing paths
      - delta: update the value of existing number paths by a delta value
      - insert: insert new items into an object or array (using `-` as array index intends appending to the end)
      - remove
      - move
    - don't update field names starts with `_` as they are readonly, such as `_变量`
    - 用户消息含【战报】且结果是胜时：禁止改 主角.生命 / 灵力 / 神识 / 精血 和 器物损耗度，禁止改战报里点过名的角色生命/生死，只许写画面。战报写「战败」时：胜负不许改；主角团生死未定，可以按叙事改他们的生命与状态
    - CRITICAL RULE: ALL `path` values MUST start with a leading slash `/`! For example, use `"/xx"` instead of `"xx"`, and `"/女性角色档案/角色名"` instead of `"女性角色档案/角色名"`. Missing the leading slash will cause fatal system errors!
    - JSON Pointer 动态键转义：路径段中的 `~` 必须写成 `~0`，`/` 必须写成 `~1`。例如任务键名 `调查A/B` 的路径必须写 `/任务/调查A~1B`，禁止直接写 `/任务/调查A/B`。
    - 变量路径使用简体中文，与变量结构严格对应
    - 【废弃路径禁令】禁止输出 `/主角/所在界`、`/主角/命轨`、`/主角/宗门-身份`、`/后宫状态`、`/天鉴`、`/成就`、`/世界/弦音`、`/世界/焦点`；界域必须写 `/世界/当前界域`，命轨必须写顶层 `/命轨`，关系必须写 `/羁绊`
    - 仅明确标注为0~100的数值字段会被钳制；人口、次数、数量等字段不得套用0~100限制
    - 【JSON语法硬约束】对象里每个字段必须写成 `"键": 值` 的形式，**冒号(:)必须在双引号之外**；严禁写成 `"键: 值"`（把键和值一起塞进同一对引号里）。例如：正确 `"灵力": 100`；错误 `"灵力: 100"`。数字与嵌套对象不要加引号，字符串值才加引号。
    - 【JSON语法硬约束】整个 <JSONPatch> 内容会被一次性解析为一个 JSON 数组，**任何一处语法错误都会导致本轮全部变量更新失败**（不只是出错的那一条）。因此生成后必须自检：所有引号/逗号/花括号/方括号成对闭合，无多余或缺失的逗号，整段可被 JSON.parse 通过。
    - 【禁止操作】严禁向 `/女性角色档案/*/当前立绘`、`/男性角色档案/*/当前立绘` 写入图片 URL；立绘由前端自动推导。
    - 【心声权限】只有 `/羁绊/*/心声` 路径允许记录人物心声。严禁在角色档案、当前在场、灵宠或任何其他路径创建心声字段。
    - 首次回复初始化规则：当用户提交开局信息时（包含道号、开局时间、境界、灵根、功法、气运等字段），必须在第一次JSONPatch中将所有开局信息解析并注入对应变量，不得遗漏任何字段。这是初始化操作，不是增量变化。具体要求：
      - 世界：初始化【当前篇章】为"地球篇"；根据开局路线初始化【当前剧情线】；写入【当前时间】【当前地点】【当前界域】【当前国家】，并根据地点建立完整【当前城市】对象
      - 境界：根据用户指定的境界查DC总表，写入"大境界小境界（DC:数值）"格式，如"金丹中期"→"金丹中期（DC:52）"
      - 灵根：直接写入用户指定的灵根
      - 功法：创建功法条目，包含类型、品阶（默认玄）、境界（默认入门）、熟练度（默认0）、效果（从词表挑）、描述
      - 气运：创建气运条目，解析效果、类型（主动/被动）、使用状态、剩余次数、压制状态
      - 身份：将用户的社会身份或主要职业写入【主角.身份】
      - 资产：按出身与身份写入符合时代的起始家底。凡俗身份至少给一个货币条目（如人民币，数量用整数），有产者写入产业；一贫如洗则留空对象，不得凭空发家
      - 社会地位：按出身写入【阶层】与两项声望初值；无名之辈写世俗声望0~5、修行界声望0、风评无名、名号无；有正式职务或宗门身份时同步写入【头衔】
      - 所处势力：用户选择宗门、世家、政府、军警、企业或其他组织出身时，创建对应势力完整对象；散修或纯凡俗身份不强行创建
      - 神念：根据初始境界生成对应描述
      - 状态：默认无异常，除非开局有特殊设定。失忆归巢必须写入完全失忆，禁止开局恢复记忆。
      - 异常状态：默认 {}。键名即状态名，禁止枚举。每条含 说明、程度(0~100)、进度(0~100)、持续。新状态 insert，变化 replace，解除 remove。失忆归巢必须 insert /主角/异常状态/完全失忆。禁止再写 堕落值。
      - 衣着：按开局着装或身份推演写入上装、下装、内衣、内裤、袜子、鞋子、配饰七项
      - 身体状态：默认写入面容、胸腹、腰臀、性器、后庭、手足为无异常；开局若受伤则写入对应部位；主角为女性时改用朱唇、乳房、美臀、小穴、菊穴、玉足
      - 修为：初始化为0（刚进入当前小境界）
      - 命轨：依据剧情写入顶层【命轨】，不得写入主角目录
      - 道心：根据出身背景设定合理初始值
      - 羁绊与在场：开局点名命运牵引人物时，同轮 insert 对应女性角色档案、当前在场互动女性、羁绊。失忆归巢：赛琳在场，亲情羁绊，阶段至少熟悉，与user的关系为被唤作妈妈的养母，主角开口称她妈妈，禁止写成血亲。尘世偕行：所选凡人女角在场，羁绊类型按用户所选，不另起主线剧本。
    - 每回合强制更新变量（即使值未变也必须在Analysis中提及判断）:
      - 世界.当前时间
      - 世界.当前地点
      - 世界.当前界域、当前国家、当前城市
      - 世界.危机程度
      - 世界.动向（滚动维持1~8条，约一半客观世界、一半主角或当前行动，旧条目必须remove）
      - 世界.政府动向（滚动维持1~8条政府行动，旧条目必须remove）
      - 世界.军事动向（滚动维持1~8条军事部署、冲突与戒备，旧条目必须remove）
      - 世界.国家动向（滚动维持1~8条国家趋势，旧条目必须remove）
      - 世界.全球动向（滚动维持1~8条跨国或全球变化，旧条目必须remove）
      - 世界.世界局势（维持1~4个宏观主题，只有真实变化时更新）
      - 讯息（维持因果NPC通信，需通过地点环境检查）
      - 互联网（滚动维持3~4个公开网络事件，旧条目必须remove）
